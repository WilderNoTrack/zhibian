# 知辨 · 辩论界面

已接入知乎官方 CLI 的站内搜索接口，并通过服务端 OpenAI 兼容接口接入 DeepSeek。页面显示真实作者、头像、认证、接口正文、AI 摘要、赞同数与原文链接；用户还可以随时向回答提问。AI 能力默认使用 `deepseek-flash`，排队 5 秒还没开始输出时自动改用 `deepseek-v4-pro`，不会对真实作者套用预设分析。

## 本地启动

安装 Node.js 22 或更新版本后，在项目目录运行 `npm run dev`，打开 http://localhost:5173 。服务端无第三方运行依赖。

AI 能力需要密钥：把 `.env.example` 复制为 `.env` 并填入 `DEEPSEEK_API_KEY`。服务启动时会自动读取项目根目录的 `.env`；已存在的系统环境变量优先，不会被覆盖。`npm test` 不读取该文件。`.env` 已在 `.gitignore` 中，不会进入仓库、接口响应或浏览器。

运行服务的 Windows 用户还需要已配置知乎官方 CLI 凭据。默认二进制路径为 `C:\Users\32390\AppData\Local\ZhihuCLI\current\zhihu-cli.exe`（来自官方 Skill 状态检查）。可用 `ZHIHU_CLI_PATH` 环境变量指定其他已安装的官方 CLI 路径，例如用户全局安装的 `C:\Program Files\ZhihuCLI\zhihu-cli.exe`。

密钥由官方 CLI 从系统凭据库读取，代码和浏览器不接收密钥。Codex 沙箱账号可能看不到当前用户的凭据库；本地服务应在已配置 CLI 的用户身份下启动。

服务只绑定 127.0.0.1，只公开 web 目录，不会公开项目资料、Skill 或凭证。可通过 PORT 环境变量修改端口。

## 已实现

- 独立辩题大厅 `/topics`：提问入口 → 今日热辩滚轮 → 分类入口 → `/debate?id=...` 辩论现场。URL 可直接打开或刷新，支持浏览器前进后退。
- 8 个常驻分类、16 个常驻辩题：情感与婚恋、职场与生存、钱与消费、家庭与代际各 3 题；教育与养娃、人生与选择、科技与 AI、影视与审美各 1 题。旧的 family/work 分类链接仍有效。
- 大厅顺序为“今日热辩滚轮 → 提问入口 → 分类入口”。今日热辩是横向滚动的多条辩论，每条卡片直接画出左方／右方两侧，不用点进去就能看出这道题在争什么；卡片标注来源（今日热榜 · 已人工核对 / 今日热榜 · AI 编排 / 换个话题），不会把轮换的题冒充成热榜。
- 独立辩题库 `/library`：列出全部辩题（人工核对 + AI 编排），支持按标题 / 立场 / 分类实时检索，并有来源与分类筛选。检索只在本机目录里查，不调用知乎。
- 每个已发布辩题均按三回合、六条真实来源编排。每回合保留条件与语境说明，不把“有条件支持”强行改成绝对立场。
- 回合卡片会按需调用服务端 AI 生成“AI 观点摘要”；摘要只概括回答原文的判断、前提和条件，不评价作者，也不补充原文之外的事实。点击“原文与来源”可阅读接口返回的正文并打开知乎完整原文。
- 分类卡桌面四列、中等屏幕两列、窄屏一列。分类页只读本地目录，不调用知乎搜索或热榜。
- 背景卡只显示接口认证和当前摘要中明确的本人自述；没有信息时明确留空。
- 长回答摘要可以展开，单条及整场来源可打开知乎原文。
- 新辩题搜索结果会自动交给 DeepSeek 做相关性筛选，只保留直接讨论该辩题的观点；它不判断左右阵营。
- 任意问题可以点“自动编排”排成一场：搜索 → AI 相关性筛选 → AI 配对 → 服务端逐字校验 → 进入同一套辩论现场。AI 抄回的原句必须能在知乎返回的正文里逐字找到，对不上的席位直接丢弃，配不出真实分歧时退回观点阅读，不补写内容。
- 配对必须真的对立：AI 要为每个回合写出“两人共同回答的是非问句”，并为每一方选定“肯定／否定”；两侧相同、或写不出共同问题的回合直接丢弃，不会把“两边其实同向”包装成正反两方。
- 编排成功的问题会收进辩题库，可再次打开；打开时重新搜索并逐字复核，来源变了就少一个回合。AI 编排的题带独立徽标，`reviewedAt` 恒为空，绝不冒充人工核对。
- 今日热辩会自动从知乎热榜收录新话题：由于热榜只有标题、没有答案，每条都要跑一遍编排才能进库。这件事在后台进行、无需点击，因此设了边界——不足 4 条才触发、每轮最多 3 条、失败进冷却、并且用关键词粗筛掉新闻与政治类头条。
- AI 质询支持用户自由提问，回答基于知乎回答全文生成，不评价答主身份，也不替用户裁决立场。
- 回顾引用原句，不生成胜负裁决。
- 桌面、平板、手机布局；键盘回合导航、对话框焦点管理、减少动态效果设置。

## 文件

前端是知乎风格的单页应用（顶栏 + 主信息流 + 右侧栏），`web/` 是唯一在用的界面。

- web/index.html：页面入口。
- web/zhihu.css：主题、布局与响应式排版。
- web/ui.js：共用标记与图标（辩题行、徽标、头像、来源链接）。
- web/data.js：按实际回合数转换的纯 UI 状态，不含演示人物。
- web/app.js：界面、交互、轮播与路由（`/`、`/topics`、`/library`、`/debate`、`/search`）。
- web/lobby.js：辩题大厅、今日热辩轮播、提问入口与分类信息流。
- web/library.js：辩题库页面的检索与筛选（纯函数，客户端过滤）。
- web/topic-ids.js：服务端目录与前端状态共用的有效辩题 ID。
- scripts/serve.mjs：本机静态服务、API 路由、缓存、限流及跨站访问防护；含热榜后台收录与关键词粗筛。
- scripts/zhihu.mjs：调用官方 CLI、规范化来源与校验原句。
- scripts/arrange.mjs：把 AI 编排结果落成座席前的逐字校验、共同问题与立场对立校验，以及不通过时的降级。
- scripts/auto-topics.mjs：辩题库的落盘与读取，按查询哈希去重、上限 80 条、原子写入；只存来源 ID 与已校验原句，并记录热榜收录状态。
- scripts/debate-seeds.mjs：20 个高对立种子辩题（开发期用模型一次性生成），与热榜一起作为收录候选。
- scripts/catalog.mjs、scripts/catalog-extra.mjs、scripts/curated-rounds.mjs：16 个常驻场次与 1 个今日热辩的编辑编排，保存来源 ID 与已核对的原句；不复制整篇回答。
- scripts/deepseek.mjs：服务端 DeepSeek 摘要、相关性筛选、自动编排、独立对立复核与质询适配器，使用 OpenAI 兼容的 chat completions 接口。
- data/auto-topics.json：运行期生成的辩题库收录（已被 .gitignore 忽略），不含回答正文。
- tests/：观看流程、真实数据边界、来源安全、自动编排校验、对立复核、辩题库检索、热榜收录与页面交互测试。
- web-classic/：上一版界面的归档，**不在服务路径上**，只为对照保留，可独立启动（见该目录下的说明）。

## 数据边界

`GET /api/topics` 返回人工目录加上本机辩题库，并会顺带触发一次后台热榜收录（不等待、失败不影响响应）；`GET /api/debate?id=...` 查询目录或辩题库条目并编排；`GET /api/debate?q=...` 对任意问题走“搜索 → AI 筛选 → AI 编排 → 逐字校验”一条龙（三步都命中缓存时不产生新的上游调用）；`GET /api/search?q=...` 返回知乎原始搜索结果；`POST /api/filter` 在新辩题搜索后批量筛选与题目直接相关的观点；`POST /api/summarize` 接收单条回答正文并返回 AI 摘要；`POST /api/critique` 接收用户问题并针对回答全文质询；`GET /api/hot` 返回官方热榜，也是后台收录的候选来源。

收录条目只写入 `data/auto-topics.json`（来源 ID + 已校验原句），不写回答正文；打开时会重新搜索并逐字复核，与人工场次共用同一套校验。它们带 `autoArranged: true` 与 `featuredSource` 标记，`reviewedAt` 恒为 null，绝不冒充人工核对。

**热榜收录会在没有点击的情况下花掉 AI 调用**（热榜只有标题没有答案，必须跑一遍编排才能进库）。边界：辩题库里热榜来源不足 4 条时才触发、每轮最多 3 条、失败进入冷却不再重试、且用关键词粗筛排除新闻与政治类头条。这是关键词匹配而非分类器，需要人工复核。

每次未命中缓存的搜索消耗一次知乎搜索调用。同一查询缓存 15 分钟，合并并发请求；单服务每小时最多 60 次未缓存查询、最多两条并行请求。遇到限流不自动重试。缓存仅在服务进程内，不写入磁盘。

AI 能力通过服务端环境变量配置：`DEEPSEEK_API_KEY` 和可选的 `DEEPSEEK_BASE_URL`（默认 `https://api.deepseek.com`）。默认模型为 `deepseek-flash`，以流式方式请求：DeepSeek 繁忙时请求会被排队，只收到 keep-alive 空行。若 5 秒内还没开始输出（可用 `ZHIBIAN_AI_QUEUE_MS` 调整），或 flash 直接报错，同一请求改发 `deepseek-v4-pro`（关闭思考模式，15 秒内须开始输出，整体上限 90 秒）；已经开始输出的回答不会被中途切换。两个模型都失败时返回“AI 服务暂时不可用”。接口返回的 `model` 字段是实际作答的模型。密钥不进入浏览器、仓库或接口响应；筛选、摘要、质询和编排结果在内存中缓存，不写入磁盘。未配置或上游失败时，界面保留原文并明确提示，不伪造 AI 结果。

自动编排的落座条件比人工编排更严：AI 返回的回答 ID 必须在本次结果中、原句必须能在该条回答正文里逐字定位（容忍空白差异，展示时回填作者原文）、一个回合必须恰好一左一右且来自不同答主、同一条回答只能用一次。任何一条不满足就丢弃该回合，绝不用生成内容补位；四步都无法形成两方对照时，退回“先看观点”的阅读模式并说明原因。`ZHIBIAN_DEBUG=1` 可在终端打印服务端错误对象，便于定位上游失败。

热榜接口仍单独缓存 30 分钟并合并并发请求，失败后冷却 5 分钟；它不再是大厅渲染的必需请求。上游可能实施比本地更严格的频控；余额充足也不保证连续批量请求成功。

已编排场次按 2026-09-14 实际查询结果人工核对。每个席位必须同时匹配原文链接中的回答 ID、所引用的原句和题目相关性关键词；来源发生变化、未返回、跑题或不再匹配时，不用虚构内容补位，失效回合会被隐藏或退回原始观点阅读。人工编排与 AI 自动编排在界面上分别标注（“已核对原句”与“AI 自动编排 · 原句已逐字校验”），两者都不替用户分阵营、不裁决胜负。

作者并未实际同场辩论；观点可能来自不同问题。原文链接保留 API 溯源参数，接口正文可能受返回范围影响，作者自述和引用中的事实未经本应用独立核实。AI 摘要只是阅读辅助，不是作者原话或 AI 裁决。

## 验证

安装开发依赖后运行 `npm test`（当前 76 项）。接口测试使用受控的上游响应，不消耗知乎额度；真实 API 联调需另行调用本地服务。浏览器视觉验收与自动测试分开记录，自动测试不代表像素布局已验收。

`tests/fixtures/editorial-sources.json` 仅保存本次核对所用的公开 API 摘要作为离线测试依据，不被应用用于填补线上结果。可手动运行 `node tests/catalog-live-smoke.mjs` 逐题联调，会消耗未命中缓存的接口调用，遇到接口限流立即停止；不是日常自动测试的一部分。
