# 界面换成知乎风格

日期：2026-09-15。本文记录界面换代这件事本身：换成了什么、怎么换的、哪些东西一起动了。

## 结论

`web/` 现在是**知乎风格**的单页应用：顶栏 + 主信息流 + 右侧栏。上一版界面原样归档在 `web-classic/`，不在服务路径上。

## 旧界面 vs 新界面

| | 旧（`web-classic/`） | 新（`web/`） |
| --- | --- | --- |
| 布局 | 单列，分区堆叠 | 顶栏 + 主列信息流 + 右侧栏 |
| 辩题列表 | 卡片网格 | 信息流行（标题、知乎原题、摘要、左/VS/右、动作） |
| 分类入口 | 八张分类大卡 | 顶部标签页 + 侧栏分类列表 |
| 提问入口 | 页面中部的搜索块 | 帖子式编辑器（头像 + 输入 + 按钮） |
| 搜索 | 结果嵌在大厅里 | 独立 `/search` 页 |
| 样式 | `styles.css` + `lobby.css` | 合并为 `zhihu.css`，另抽 `ui.js` 放共用标记 |

新界面**继承了此前所有数据纪律**，没有为了好看而放松：

- `人工核对` / `AI 编排` 徽标（`originBadge`），AI 题不冒充人工核对。
- 今日热榜来源单独打 `今日热榜` 徽标；轮换进来的普通题不会被打成热榜。
- 幻灯片保留「知乎原题：…」小字，润色后的标题不隐藏原始出处。
- 辩论现场仍有「已核对原句」标记、每回合的编排说明、来源弹窗与原文外链。
- 轮播、`/api/preview` 的逐字复核与「复核：左方 … 右方 …」都照旧。

## 怎么换的

1. 旧 `web/` → `web-classic/`（**复制**，不是删除；此仓库没有 git，没有回头路）。
2. `web-zhihu/` → `web/`。
3. `scripts/serve.mjs` 的页面白名单加入 `/search`（新界面多了一个页面路由；漏加会 404，这个坑此前踩过）。
4. 原 `scripts/serve-zhihu.mjs` 只是「在另一个端口伺服另一套前端」的胶水，换代后成了重复代码。
   把它改造成 `web-classic/serve-classic.mjs`：服务归档目录、端口 5175、`/api/` 依旧交给
   `scripts/serve.mjs`，这样归档仍可单独启动对照，而主仓库只剩一个服务入口。

## 顺手修掉的一处隐患

`web/app.js` 里有一个**裸 NUL 字节**（`source.id + '\0' + text` 里的分隔符被写成了真实的 0x00，
而不是 `\u0000` 转义）。它能跑，但让整个文件被 grep 当成二进制、也容易被编辑器或格式化工具吃掉。
已改成 `'\u0000'`，文件恢复为纯文本。

## 后续调整：删掉编排说明、突出 AI 质询（2026-09-15）

用户的两次要求：`把所有ai编排说明删了`、`把ai质询按钮做得显眼一点`。

### 删掉的三处说明文字

| 位置 | 原内容 | 处理 |
| --- | --- | --- |
| 回合面板顶部的 `.host-card` | 标签「AI 编排说明」/「编排说明」+ 一句本回合说明 | 整块删除 |
| 来源行下方的 `.arrangement-note` | 「AI 自动编排：原句已与知乎返回的正文逐字校验…」整段 | 删除 |
| 观点卡内的 `.context-note` | AI 写的每席说明（如「强调机会。」）；人工题则是六张卡重复同一句免责声明 | 删除 |

删除的理由不只是"用户要求"：第三项在人工题上是**六张卡重复同一句话**，属于样板噪音；而它的内容已经被右侧「阅读提示」覆盖。

**删除后仍然保留的标注**（项目的硬底线不能丢）：

- 顶部的 `AI 自动编排 · 原句已逐字校验` 徽标 / 人工题的 `已核对原句` 徽标；
- 每张卡的引句标签：`原回答原句 · 已逐字校验` / `原回答中的核对原句`；
- 右侧「阅读提示」：**作者并未实际同场辩论，观点可能来自不同问题。阵营与回合是本应用的编排，不代表谁赢。**
- 来源行仍显示 `知乎 API · 获取于 … · 编排模型 deepseek-flash` 与 `N 条来源`。

也就是说：**"这场是人编的还是 AI 编的"仍然一眼可辨，只是不再用整段文字解释。**

### 质询按钮

原来 `.action-button.critic-button` 和旁边的「原文与来源」是同一档的浅色次要按钮。现在给 `.answer-actions .critic-button` 实心主色（`--brand` 蓝底白字、高 34px、加粗），次要动作保持透明底 —— 观点卡上的主次一眼分明。

实测：`background-color: rgb(23, 114, 246)`、`color: rgb(255,255,255)`、`height: 34px`；同排的 `.source-button` 仍是透明底。

### AI 观点摘要改成一句一行

用户的意见是这一块读起来累。

模型返回的摘要是**一整段连贯文字**，读的人却是一句一句看的。现在在渲染前把摘要按句切分，每句独占一行：

- 切分点：`。！？!?` 与 `；;`，保留标点；原有换行也保留。
- 实现放在 `summaryLines()`（`web/app.js`），**只改换行位置，不动一个字**；用 `textContent` 写入，不引入 HTML。
- 样式加 `white-space: pre-line` 与行高 1.9，让换行真正显示出来。

实测：一条 6 句的摘要渲染为 6 行（`textContent.split('\n').length === 6`，`white-space: pre-line`）。

注意一个边界：**切分只认标点，不认语义**。摘要里若出现「他说"…。"」这种引号内的句号，会在那里断行。因为摘要本身很短且不改写文字，这个取舍可以接受；如果以后发现断行位置别扭，改成按「句号 + 后一个字符不是引号结尾」来切即可。

测试：`tests/zhihu-ui.test.mjs` 的摘要桩改成三句话，断言渲染结果正好三行。`npm test` 84 项全过。
