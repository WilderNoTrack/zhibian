# 任意问题自动编排（自由辩题）

日期：2026-09-14。本文区分「已实现并验证」「仍未验证」「仍待验证」。

## 目标

把自由搜索从「一列相关观点」升级成「排成一场」：用户输入任意问题后，AI 先判断哪些回答直接符合这次辩题，再把其中真正存在分歧的回答配成对照回合，进入与人工编排场次相同的辩论现场。

## 已实现

### 服务端

- `GET /api/debate?q=<问题>`：搜索 → AI 相关性筛选 → AI 自动编排 → 服务端逐字校验，返回与人工编排一致的数据形状（`rounds`、`lenses`、`hosts`、`left/right`、`questions`、`items`），并带 `autoArranged: true`。
- `scripts/deepseek.mjs` 新增 `arrangeWithDeepSeek`：只输出 JSON 对象；提示词明确要求原句「逐字复制、10–60 字、不得改写或拼接」，并要求每条回答只用一次、凑不出真实分歧就少给回合。
- `scripts/arrange.mjs`（新）：`locateQuote` / `verifyArrangement` / `autoDebate`。落座条件：
  1. 回答 ID 必须来自本次筛选结果，否则 `UNKNOWN_SOURCE`；
  2. 原句必须能在该条回答正文里定位，否则 `QUOTE_NOT_VERBATIM`；容忍空白差异，定位成功后**回填作者原文**而不是模型复述的那一份；
  3. 一个回合必须恰好两条、一左一右、作者不同，否则 `SIDES_NOT_OPPOSED` / `SAME_AUTHOR`；
  4. 同一条回答只能用一次，否则 `DUPLICATE_SOURCE`；
  5. 模型必须能说出这一回合两人共同回答的那个是非问句（`sharedQuestion`），否则 `NO_SHARED_QUESTION`；
  6. 两侧必须落在**相反的立场**上（`stance` 一为「肯定」、一为「否定」），否则 `STANCE_NOT_OPPOSED`。
  任何一条不满足即丢弃该回合，返回的 `verification.dropped` 记录原因。
- 相关性筛选后直接相关不足 4 条时不调用编排；一条都没有时页面给出「没有找到直接相关的观点」，不展示未经筛选的原始结果。
- 三步各自有内存缓存（搜索 15 分钟、筛选与编排按内容键），重复问同一个问题不产生新的上游调用。

### 对立判据（2026-09-14 收紧，针对「正方不完全正、反方不完全反」）

第一版提示词把「同一个判断依赖了不同条件」也算作分歧，结果出现了两类不合格配对：

- 两条方向相同（都支持或都反对），只是方案、归因或条件不同；
- 其中一条根本没有表态，只是陈述事实或经历。

改法是三层，从软到硬：

1. **提示词**写明唯一合格标准（把两条并排能读成「一个说该，另一个说不该」），并逐条列出不合格情形，附一组好例/坏例。
2. **新增 `sharedQuestion` 字段**：模型必须先写出两人共同回答的是非问句，写不出就删掉该回合。
3. **新增 `stance` 字段 + 确定性守卫**：每方只能填「肯定」或「否定」，两侧相同即整回合丢弃（`STANCE_NOT_OPPOSED`）。

### 自由提问收录（编入辩题大厅）

- 编排成功的自由问题会落盘到 `data/auto-topics.json`（`.gitignore` 已忽略，属运行期数据）。只保存来源 ID 与已校验的原句，不保存正文。
- 按 `auto-<查询哈希>` 去重（upsert，最新的排前），上限 60 条，原子写入（临时文件 + rename）。
- `GET /api/topics` 动态返回「人工目录 + 收录的自由提问」；`GET /api/debate?id=auto-…` 打开时**重新搜索并逐字复核**，与人工场次走同一套 `arrangeDebate` —— 原句对不上就少一个回合，不补位。
- 大厅把两类**分区展示**：人工场次仍在 8 个分类与「最近新增」里，自由提问单独进「自由提问收录」并带 AI 徽标；卡片文案分别是「N 组已核对观点」与「N 组 AI 编排观点」。收录条目 `reviewedAt` 恒为 `null`，不会被标成已人工核对。
- 只有真正产出过至少一个合格回合的问题才会被收录；没成场的不收录。

### 前端

- `/debate?q=<问题>` 路由；`data.js` 用 `q:` / `auto-` 前缀区分自由辩题与目录白名单，不污染 `topic-ids.js`。
- 搜索结果区在直接相关 ≥ 4 条时出现「自动编排这 N 条」入口。编排由用户点击触发，不自动跳转（与「AI 只在用户主动点击时介入」一致）。
- 自动编排场次在界面明确分区标注：`AI 自动编排 · 原句已逐字校验` 徽标、`AI 编排说明` 标签、`原回答原句 · 已逐字校验` 引句标签、页脚说明「未通过校验的席位会被直接丢弃，不会用生成内容补位。这是观点对照，不是真人同场辩论。」人工编排场次仍显示「原回答中的核对原句 / 编排说明」。
- 每回合额外显示「这回合两人回答的是同一个问题：…」以及每位答主的 `AI 判定这一方：肯定 / 否定`，让读者能看见 AI 认定他们对立在什么地方。
- 编排成功后客户端会作废目录缓存，返回大厅即可看到新收录的题目。

## 验证

- `npm test`：64 项通过。新增 `tests/arrange.test.mjs`（含 `NO_SHARED_QUESTION`、`STANCE_NOT_OPPOSED` 两项守卫）、`tests/auto-api.test.mjs`、`tests/auto-topics.test.mjs`（收录去重、上限、损坏文件容错、收录条目字段脱敏、打不开已失效的来源）、`tests/ui.test.mjs` 的前端编排与收录测试。覆盖：原句改写被丢弃、来源不存在、同源复用、同作者配对、左右未对立、说不出共同问题、两侧立场相同、回合不足、相关数不足不触发编排、零相关不展示原始结果、缓存不重复调用、AI 未配置时报错而非展示内容。
- 真实链路冒烟（2026-09-14）：用真实知乎搜索返回（问题「毕业后要留在大城市吗」，10 条结果、筛选后 6 条）跑通到 `/api/debate?q=` 的完整响应 —— 编排出 1 个回合，`verification.dropped` 为空，两个席位分别是真实答主「巴洛克」「Demi Yang」，引句为对应回答正文的逐字片段，`sourceUrl` 指向真实知乎链接。

## 真实模型实测（2026-09-14，deepseek-flash）

验证顺序：先用本地桩替代 DeepSeek，验证「搜索 → 筛选 → 编排 → 逐字校验 → 页面数据」这条链路；随后在本地 `.env` 配好密钥，用真实 deepseek-flash 重跑。

结果：

- 摘要 4 例：全部忠实于原文，关键限定没有被反向改写。原文「年薪不高」保持为「年薪不高」，「事业编的教师」被保留，没有出现原文之外的事实补充。
- 自动编排 3 个问题（该不该读研 / 兴趣能不能当职业 / 该不该跟父母住一起）：3/3 返回合法 JSON。AI 共提交 9 个回合，落座 8 个，丢弃 1 个 —— 原因是 `DUPLICATE_SOURCE`（同一条回答被 AI 用在了两个回合），被服务端拦下，没有进入页面。
- 独立复核（不走服务端校验，直接在返回结果里重新比对）：8 个回合共 16 条原句，全部是该条回答正文的逐字子串。
- 端到端耗时约 5–6 秒/问题（含一次知乎搜索）。

### 收紧判据的前后对比

同一组四个问题（该不该辞职考研 / 要不要生二胎 / 大学生该不该兼职 / 该不该跟朋友合伙创业），改前改后各跑一遍，由人工逐条判断「两方结论方向是否真的相反」：

| | 改前 | 改后 |
| --- | --- | --- |
| 落座回合 | 9 | 9 |
| 明显合格 | 4（约 44%） | 7 |
| 略勉强 | 3 | 2 |
| 明显不合格 | 2 | 0 |

改前的典型不合格：左「真没必要辞职考研，不值当」配右「我的方案是不辞职，直接考非全 MBA」——两条都反对辞职；左「这类兼职不绑定固定线下场地，产出可以收纳成作品集」纯属描述，却被当成一方。

改后这类「两边其实同向」「一方没表态」的配对没有再出现。**注意：`STANCE_NOT_OPPOSED` 守卫本身一次都没有触发**，说明起作用的其实是提示词里「每个席位必须明确表态、两侧必须相反」这一要求，模型在提交前就自己筛掉了同向配对；守卫是安全网，不是主要功臣。

残留的失效模式（与改前不同）：个别席位的引句更接近「理由或片段」而不是一句判断，例如「有些人辞职，不是因为看不到未来。」这种。方向已经是相反的，但句子本身不够像结论。回合数没有下降，说明不是靠少给回合换来的质量。

## 仍未验证

- 上述对比每组只覆盖 4 个问题，样本量小；同题重跑仍有波动（「该不该裸辞」一次给出两条偏弱的配对，另一次则正常）。
- 连续批量提问下的稳定性、上游限流时的行为没有实测。
- 真实模型下的 token 消耗与额度占用未统计。
- 「引句是不是一句判断」目前**没有确定性校验手段**，只能靠人工读；`stance` 守卫只能保证两侧方向相反，不能保证引句本身是一句判断。

## 本地密钥配置

服务启动时会读取项目根目录的 `.env`（见 `.env.example`）。已存在的系统环境变量优先，不会被 `.env` 覆盖；`npm test` 不会读取该文件，因此测试永远不会拿到真实密钥。`.env` 已在 `.gitignore` 中。
