# 大厅改版与辩题库

日期：2026-09-14。本文区分「已实现并验证」「未验证 / 已知取舍」。

## 这次改了什么

1. 删掉大厅的「最近新增」与「自由提问收录」两个分区。
2. 提问搜索框放在「今日热辩」正下方。
3. 「今日热辩」做成轮播：一次一道辩题、5 秒自动切换、底部圆点可点。
4. 左侧导航新增「辩题库」（`/library`），支持检索与筛选。
5. 删掉「从你关心的生活开始」这个板块标题；热辩与 AI 辩题不再单列，而是归入八个分类。
6. 轮播辩题的标题由模型润色成对立鲜明的问法，不再照抄知乎原标题。
7. 收录候选不再只有热榜，还有一批种子辩题（见下）。

大厅现在的结构是：今日热辩轮播 → 提问入口 → 八个分类。

## 今日热辩轮播

- 结构：`.carousel` → `.carousel-viewport`（裁切）→ `.carousel-track`（`display:flex`，用 `transform: translateX(-N*100%)` 平移）→ 8 个 `.carousel-slide`，每张一张辩题。
- **一次一道**，5 秒自动切到下一道（`CAROUSEL_INTERVAL = 5000`）。
- **底部圆点**：每张幻灯片一个 `.carousel-dot`，当前张变成蓝色长条；点击圆点直接跳到那一道。左右箭头逐张切换。
- 自动轮播在**悬停或聚焦**时暂停（`pointerenter/leave`、`focusin/focusout`），`prefers-reduced-motion: reduce` 时不自动播。
- **每张幻灯片左右两格放答主名 + 逐字核对过的原句**，不是 AI 短标签：
  - 数据来自 `GET /api/preview?id=<辩题ID>`：服务端拿该题配置跑一次 `arrangeDebate`（人工题与收录题一视同仁），取第一回合两席，返回 `{left:{name,quote}, right:{name,quote}, sharedQuestion}`。
  - 因为重新走了 `arrangeDebate`，原句此刻一定还在知乎返回的正文里逐字存在；来源变了就返回 `preview: null`，前端退回短标签，**不会展示已经对不上的话**。
  - 结果按辩题 ID 缓存在内存（上限 40 条），转回同一道不再重新请求。
- 标题用 `debateTitle`（模型润色后的对立问法），下方以小字保留「知乎原题：…」，不隐藏原始出处。
- 已看记录只记**真正展示过**的那一张（不是整批），所以下次进大厅真的会换新的进来。
- 定时器走 `window.setInterval` 而不是裸全局：测试环境会把 `window` 换成 jsdom，裸 `setInterval` 落在 Node 上会让 `node --test` 的进程永远退不出去（实测挂满 6 分钟）。

## 收录候选：热榜 + 种子辩题

- 热榜条目：关键词粗筛（`FEATURED_WANT` / `FEATURED_SKIP`）之后按排名取。
- 种子辩题：`scripts/debate-seeds.mjs` 里的 20 个高对立、高热度话题（彩礼、带娃、跳槽、裸辞、AI 写作业…）。**这份清单是开发期用模型一次性生成的，运行时零成本**；每一条仍然要走完「搜索 → 筛选 → 编排 → 逐字校验」才能进库，找不到对立双方就不收录。
- 两者合并成候选池，热榜在前；每轮最多尝试 3 条，失败进冷却，已评估过的不再重复。
- 触发条件：辩题库里「热榜或种子来源」的辩题少于 4 条时才会在大厅加载时后台补收。

## 双方回答可以来自不同问题页

相关性筛选的提示词已改为：**只要一条回答能作为这道辩题某一方的依据即可，不必来自与辩题字面相同的问题**。例如辩题是「该不该裸辞」，一篇讲「为什么我后悔裸辞」的回答可以算「不该」一方。编排提示词也加了一句：两条尽量来自不同问题。

实测：收录下来的回合里，绝大多数两侧来自不同的知乎问题页，只有少数恰好同页。放宽的是"入选门槛"，不是"对立判据"。

## 独立对立裁判（2026-09-15，针对「反方其实是正方观点」）

### 之前的做法错在哪

第一版用一个 `stance` 字段要求 AI 为每一方填「肯定／否定」，两侧相同就丢弃。问题在于：**这个字段是编排那一次调用自己填的，等于让考生自己批卷。** 模型可以一边说两句同向，一边把它们标成一正一反，守卫照样放行 —— 用户连续两次报「实用礼物那题反方其实是正方观点」，根因就在这里。

### 现在的做法

编排完成后，把每一对**单独**交给另一次调用做裁判（`verifyOppositionWithDeepSeek`，温度 0）：

1. **裁判看到的是引句 + 引句前后的原文**（各约 140 字），不是只有那一句。因为一句话单独看是一种立场，读了下文可能正好被推翻（「有人说…但我不同意」）。裁判**看不到**编排给的 `stance`／`note`／`reason`，所以没法照着抄。
2. 裁判的任务不是"这两句像不像对立"，而是**"这两位作者本人是不是站在相反的两边"**。要求先分别说出两位作者本人的立场，再判断 —— 引句里如果是转述别人的观点，不算作者本人的立场。实测这一步能识破「引句截在转述上、下文立刻反驳」的情形。
3. 裁判还要为每一方填 `leftSide` / `rightSide`（只能「支持」或「反对」）。

### 两道确定性守卫（不依赖裁判的勾选）

拿到的判定还要再过两道**不信任裁判**的检查（`judgeVerdicts`），任一不满足即丢弃该回合：

- 裁判自己复述出来的两个立场**字面相同** → 丢弃。
- 裁判给出的两个 `side` **相同** → 丢弃。

这两条专门用来兜住"裁判勾了 opposed=true，但它自己的描述说明两边其实一致"这种情况。被丢弃的回合记为 `NOT_REALLY_OPPOSED`，不会补位。

### 实测

- 受控对照：把「左支持实用礼物／右是引句截了转述、下文其实也支持」交给裁判，它判 **不对立**，理由写明「右方引句是转述他人观点，作者本人随后反驳并支持实用礼物」。
- 真实收录：「服务型游戏」那题 AI 提交 2 回合，**1 个被判同向丢弃**；「全球变暖」那次两边都写"弊大于利"的配对在加上二元立场守卫后不再出现。
- 用 `GET /api/preview` 与轮播页面都能看到裁判的复核结论（「复核：左方 … ；右方 …」），让"这两边真的对立"变成可核对的说法而不是断言。

**仍未解决**：裁判本身也是模型，仍会偶尔放过同向的一对。它把命中率从「大约一半」提到「大多数」，不是 100%，仍需要人工抽查。

## 顺带修掉的截断 bug

`AI 相关性筛选` 一次把 20 条回答塞进一次调用，输出超出 `max_tokens` 被**截断**，JSON 解析失败 → 整条链路报 `AI_UPSTREAM`。这个 bug 一直在，只是表现为"偶发失败"，很容易误判成上游抖动。修法：

- 筛选改为**分批**（每批 8 条）再合并判定。
- 解析改为**容错**：响应被截断时，抢救出已经完整的条目，而不是整体丢掉；没有判定结果的 id 按"不相关"处理（保守一侧）。
- 各步的 `max_tokens` 按实际需要重设（筛选 2000、编排 3000、质询 700、裁判 1000）。
- 解析失败时在 `ZHIBIAN_DEBUG` 下打印响应长度与结尾，方便判断是截断还是模型没按格式输出。

## 标题润色与分类归档

编排这一步除了配对，还会让模型输出两个附加字段：

- `debateTitle`：对立鲜明的辩题问法（≤18 字）。原标题已经够锋利时原样填入，不允许留空。
- `category`：只能从八个手工分类里**原样复制**一个，提示词里附了每个分类的含义说明；种子辩题直接沿用人工指定的分类，模型的选择只在合法时才被采纳。

分类为空或未知的辩题**不会**出现在分类网格里（也不会再出现无名分类卡），但仍在轮播和辩题库中可见。

## 辩题库 `/library`

- 列出全部辩题：人工核对 + AI 编排，卡片上有 `人工核对` / `AI 编排` 徽标。
- 顶部检索框对标题、立场标签、简介、分类做实时匹配（输入即筛，不调上游）。
- 两行筛选：来源（全部 / 人工核对 / AI 编排）与分类。
- 打开任意一题都会重新拉取来源并逐字核对原句，与人工场次共用同一套校验。

## 验证

- `npm test`：89 项通过。新增/更新了辩题库检索、轮播结构、收录持久化、热榜与种子收录、preview 接口，以及**独立裁判**的测试（同向配对必须被丢弃、且不经编排的标签污染、裁判自述相同则推翻其勾选）。
- 真实链路（2026-09-14/15）：清空后重建，收录 4–6 条；每条都有润色标题与分类；逐回合审计确认两侧多来自不同问题页。
- 浏览器实测：轮播 8 张幻灯片、8 个圆点、5 秒自动切换（`transform: translateX(-600%)`）、幻灯片上读到真实答主名与逐字原句。

## 未验证 / 已知取舍

- **四处 AI 调用**：筛挑选材（每 8 条一批）、编排、独立对立复核、轮播 preview；加上热榜/种子收录。各自都有缓存与边界，但合起来已经明显偏离「AI 只在用户主动点击时介入」的原则。若要收紧，可改成显式按钮。
- **对立复核不是 100%**：裁判仍会偶尔放过同向的一对，需要人工抽查。它看到的是引句前后各约 140 字，更远的上下文仍可能推翻判断。
- **分类归档靠模型 + 8 个固定分类**：没有"环境/社会"类，像「全球变暖利弊」这类题只能被塞进最接近的分类。附上分类含义后好转，但仍会有归错的。
- 关键词粗筛只有几条规则，没有系统性回归。
- **移动端（≤600px）没有实机验收**，只有读 CSS 的推断。本机 `agent-browser` 的设备模拟在 Windows 上不可用（`device_list is only available on macOS with Xcode`），`viewport` 命令也未实现。
- 收录上限 80 条，超出后最旧的会被挤掉。
